## 4. ตรวจรับคืน (UC-18) + ค่าปรับ (UC-36)

แท็บ: ทั้งหมด (กำลังยืม + รอตรวจรับ) / รอตรวจรับคืน / เกินกำหนด / คืนบางส่วน / ค้างชำระ (ข้อ 8)

| บนจอ | Model.field | หมายเหตุ |
|---|---|---|
| เลขที่, ผู้ยืม, รูปตอนแจ้งคืน, หมายเหตุ นศ. | `BorrowRequest`, `ReturnRequest.return_photo/note` | |
| ☑ รับคืนชิ้นนี้ (ชิ้นที่ นศ. แจ้งคืนติ๊กให้อัตโนมัติ) | `ReturnItem` | ปุ่ม ✓ เลือกทั้งหมด |
| สภาพที่ นศ. แจ้ง → ผลตรวจจริง | `ReturnItem.condition_status` | ปกติ / ชำรุด / สูญหาย |
| กำหนดคืน, ค่าปรับคำนวณอัตโนมัติ | `BorrowItem.due_date`, `ReturnItem.fine` (`compute_fine` จากเฟส 1) | |
| ยอดค่าปรับที่เก็บจริง + เหตุผล | `ReturnRequest.custom_fine`, `fine_reason` | ว่าง = ผลรวมอัตโนมัติ |
| ☐ ชำระค่าปรับแล้ว | `ReturnRequest.fine_paid` | |
| ยอดชดใช้ของหาย (ค่าเริ่มต้น = ราคาจัดซื้อ × จำนวน) + ☐ ชำระแล้ว | `ReturnItem.lost_compensation`, `lost_paid` | ตอบคำถามที่ค้างจาก M3: เริ่มจากราคาจัดซื้อ แก้ได้ (ตาม UC-18 ข้อ 3) |
| ✓ ยืนยันรับคืน | `ReturnRequest.status = RETURNED`, `inspected_by`, `returned_at` · คำขอ → `RETURNED` (คืนครบ) / `BORROWING` (ยังค้าง) | ข้อความ "คืนแล้ว X ชิ้น (ยังค้างอีก Y ชิ้น)" |

ผลตรวจต่อชิ้น:

| ผล | ครุภัณฑ์ | วัสดุคงทน |
|---|---|---|
| ปกติ | → `AVAILABLE` + แจ้งคิวถัดไป | `qty_available += จำนวน` + แจ้งคิวถัดไป |
| ชำรุด | → `DAMAGED` (+ หมายเหตุลง `Equipment.note`) → โผล่ในหน้าครุภัณฑ์เสียหาย (UC-35) | ข้อ 4 |
| สูญหาย | → `LOST` (ไม่นับในคลังอีก) + ยอดชดใช้ | `qty_total -= จำนวน` + ยอดชดใช้ |

## 5. ประวัติทั้งระบบ (UC-19) — รอบ 6b

แท็บตามคำขอ (1 แถว = 1 คำขอ) / แท็บติดตามรายชิ้น (1 แถว = 1 ครุภัณฑ์: สถานะ, ผู้ถือครอง + เบอร์, ที่ตั้งปัจจุบัน, กำหนดคืน) · ค้นหา เลขที่/ชื่อ/รหัส นศ./asset tag · กรองสถานะ + ช่วงวันที่ · หน้ารายละเอียด: ผู้ปล่อยของ/เวลา, ผู้ตรวจรับ/เวลา, รูปก่อนยืม/ตอนคืน, ค่าปรับ/ค่าชดใช้

## 6. ครุภัณฑ์เสียหาย (UC-35) — รอบ 6b

แท็บ 1 ในคลัง: ครุภัณฑ์ `DAMAGED`/`MAINTENANCE`/`RETIRED` ตัวกรองย่อย · ปุ่มเดี่ยว+กลุ่ม: 🔧 ส่งซ่อม (→ `MAINTENANCE`), ✅ ซ่อมเสร็จ (→ `AVAILABLE` + แจ้งคิว), 📦 ปลดระวาง (ไม่ต้องใส่เหตุผล) · แท็บ 2 แจ้งซ่อมจาก นศ.: รับเรื่อง (→ `IN_PROGRESS`), ปิดงาน (→ `RESOLVED`) · ว่าง → "ไม่มีรายการในขณะนี้"

## 8. ต้องตัดสินใจ

1. **แบ่งรอบ**
   - **แนะนำ:** 6a = UC-16, 17, 18, 36 (ปิดวงยืม-คืนให้ครบก่อน) → commit → 6b = UC-19, 35
2. **ชิ้นที่ติ๊กออกตอนปล่อยของ** — UC-17 บอก "ตัดออกจากคำขอโดยไม่แตะสต็อก" แต่ระบบเราจองของไว้ตั้งแต่ส่งคำขอแล้ว (ตัดสินใจ M3 ข้อ 1)
   - **แนะนำ:** ลบแถวรายการนั้นออกจากคำขอ (ตาม mapping `16`) และ **คืนของที่จองไว้เข้าคลัง** — ผลสุดท้ายเท่ากับ "ไม่ได้ตัดสต็อก" ตาม UC
3. **รับคืนโดยที่นักศึกษาไม่ได้แจ้งคืนในระบบก่อน** (นักศึกษาถือของมาที่เคาน์เตอร์เลย)
   - **แนะนำ:** ได้ — เจ้าหน้าที่เปิดคำขอที่กำลังยืมจากแท็บ "ทั้งหมด/เกินกำหนด" แล้วติ๊กรับคืนเองได้ (ไม่บังคับรูปฝั่งเจ้าหน้าที่) · ถ้ามีการแจ้งคืนจากนักศึกษา ชิ้นที่แจ้งจะติ๊กไว้ให้
4. **วัสดุคงทนที่คืนมาแบบชำรุด** — UC บอกแค่ครุภัณฑ์ (→ เสียหาย) แต่วัสดุคงทนไม่มีสถานะรายชิ้น
   - **แนะนำ:** ไม่คืนเข้าจำนวนพร้อมยืม และตัดออกจากจำนวนทั้งหมด (`qty_total −`) เหมือนของหายแต่ไม่มีค่าชดใช้ · ซ่อมเสร็จแล้วเจ้าหน้าที่เพิ่มจำนวนกลับในหน้าแก้ไขสิ่งของ (M7)
   - หรือ: คืนเข้าคลังตามปกติ แล้วให้เจ้าหน้าที่จัดการเอง
5. **"สร้างรายการแจ้งซ่อมอัตโนมัติ" เมื่อครุภัณฑ์คืนมาชำรุด** (UC-18 ข้อ 3)
   - **แนะนำ:** ไม่สร้างแถว `DAMAGE_REPORT` (ตารางนั้นเป็นของนักศึกษาแจ้งเอง) — ครุภัณฑ์ที่เปลี่ยนเป็น "เสียหาย" จะไปโผล่ในแท็บ 1 ของหน้าครุภัณฑ์เสียหาย (UC-35) อยู่แล้ว พร้อมหมายเหตุอาการ
6. **กันของไว้ให้คนที่ถึงคิว** (ค้างจาก M3) — ตอนนี้ถ้าของคืนมาแล้วแจ้งคิวถัดไป คนอื่นยังใส่ตะกร้าแย่งได้
   - **แนะนำ:** กันไว้ให้ผู้ที่ถึงคิว (`NOTIFIED` ภายใน 1 วัน และ `CONFIRMED` ภายใน 1 วันหลังยืนยัน) — คนอื่นเห็น "จองไว้ให้ผู้รอคิว" ใส่ตะกร้าไม่ได้ · เลยเวลาแล้วไม่มายืม → หมดอายุ เลื่อนคิวถัดไป
   - หรือ: ไม่กัน (ใครมาก่อนได้ก่อน คิวเป็นแค่การแจ้งเตือน)
7. **แจ้งเตือนนักศึกษาเมื่อปล่อยของ/ปฏิเสธ** (UC-17 "ทุกกรณีส่งแจ้งเตือน")
   - **แนะนำ:** บนหน้าเว็บอย่างเดียวเหมือน M3 ข้อ 5 (นักศึกษาเห็นสถานะ/เหตุผลในหน้าหลัก) · อีเมลภายหลัง
8. **แก้ค่าปรับ/บันทึกชำระหลังรับคืนไปแล้ว** — นักศึกษามักจ่ายทีหลัง
   - **แนะนำ:** เพิ่มแท็บ "ค้างชำระ" ในหน้ารับคืน แสดงรอบคืนที่ค่าปรับ/ค่าชดใช้ยังไม่ชำระ แก้ยอดและติ๊กชำระได้ตลอด
9. **แดชบอร์ด** — mapping พูดถึงกราฟรายสัปดาห์/เดือน
   - **แนะนำ:** การ์ดตัวเลข 6 ใบ + ตารางคำขอรอตรวจล่าสุด · ไม่ทำกราฟในรอบนี้
10. **แอดมินแก้ค่าปรับได้ไหม** (UC-36 actor มีแอดมิน แต่เมนูแอดมินไม่มีหน้ารับคืน)
    - **แนะนำ:** รอบนี้เจ้าหน้าที่เท่านั้น · แอดมินแก้ได้ผ่าน `/admin/` ไปก่อน
