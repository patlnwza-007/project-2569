## 3. ฟอร์มเพิ่ม / แก้ไข (UC-20)

| ช่อง | Model.field | เพิ่ม | แก้ไข |
|---|---|---|---|
| ชื่อ, ที่ตั้ง, หน่วยนับ, ราคาจัดซื้อ, รายละเอียด | `Item.*` | ✅ | ✅ |
| รูป | `Item.image` | ✅ (ไม่เกิน 5 MB, ข้อ 8) | ✅ เปลี่ยน/ลบได้ |
| ประเภท | `Item.item_type` | ✅ เลือก 3 ประเภท → ช่องข้างล่างเปลี่ยนตาม | 🔒 เปลี่ยนไม่ได้ (ISA disjoint) |
| จำนวนทั้งหมด (วัสดุ / วัสดุคงทน) | `qty_total` (+ `qty_available` เท่ากัน) | ✅ | ✅ ปรับได้ (ข้อ 5) |
| วันยืมสูงสุด, ค่าปรับ/วัน | `max_borrow_days`, `fine_rate_per_day` | ✅ วัสดุคงทน + ครุภัณฑ์ | ✅ |
| จำนวนชิ้น + กล่อง asset tag ทีละชิ้น (ครุภัณฑ์) | `Equipment.asset_tag` × N แถว | ✅ กรอกเองทุกชิ้น ไม่สร้างอัตโนมัติ | ❌ ซ่อน (UC-20 ข้อ 4) |
| สถานะ | `base_status` / `Equipment.status` | ตั้ง `AVAILABLE` อัตโนมัติ | ❌ ไม่อยู่ในฟอร์ม → ใช้หน้าเปลี่ยนสถานะ (ข้อ 6) |

เพิ่มครุภัณฑ์ N ชิ้น = สร้าง N แถว `ITEM + EQUIPMENT` คัดลอกข้อมูลรุ่นให้ทุกชิ้น ภายใน transaction เดียว (asset tag ซ้ำแม้แต่ชิ้นเดียว → ไม่บันทึกทั้งชุด)

## 4. เปลี่ยนสถานะ (UC-23)

| ประเภท | ตัวเลือกที่ให้เลือกเอง | เก็บที่ |
|---|---|---|
| ครุภัณฑ์ | พร้อมใช้งาน · ครุภัณฑ์เสียหาย · ส่งซ่อมคลัง · ปลดระวาง | `Equipment.status` + หมายเหตุ → `Equipment.note` |
| วัสดุคงทน | ข้อ 3 | `Item.base_status` |

- **ปลดระวาง** ไม่ต้องกรอกเหตุผล · สถานะอื่น **บังคับกรอกหมายเหตุ** (UC-23 ข้อ 4)

## 8. ต้องตัดสินใจ

1. **คอลัมน์ CSV ขัดกัน** — UC-24: `name,type,qty_total,max_borrow_days,fine_rate_per_day` · mapping `24`: เพิ่ม `location, unit, purchase_price, description, asset_tag, status` · mockup: มี `category_id`
   - **แนะนำ:** `name,type,location,unit,purchase_price,description,qty_total,max_borrow_days,fine_rate_per_day,asset_tag` — ครอบคลุม UC + mapping · ครุภัณฑ์ 1 แถว = 1 ชิ้น และ **บังคับมี asset_tag** (UC-20 ห้ามสร้างรหัสอัตโนมัติ) · ไม่มี `category_id` · สถานะเริ่มต้น `AVAILABLE` เสมอ (ไม่มีคอลัมน์ status)
2. **ลบวัสดุที่เคยถูกเบิกแล้ว** — UC-22 บอกลบถาวร แต่ถ้าลบ ประวัติการเบิกเก่าจะเสีย (ฐานข้อมูลกันไว้ไม่ให้ลบอยู่แล้ว)
   - **แนะนำ:** ลบได้เฉพาะวัสดุที่ยังไม่เคยมีในคำขอยืมใด · ถ้าเคยถูกเบิก → แจ้งว่าลบไม่ได้ และมีปุ่ม "ปิดการใช้งาน" (`base_status = INACTIVE` นักศึกษามองไม่เห็นแต่ประวัติอยู่ครบ)
3. **สถานะของวัสดุคงทน** — UC-23 บอกเปลี่ยนสถานะวัสดุคงทนได้ แต่ ERD เก็บแค่ `ITEM.base_status` (AVAILABLE / DAMAGED / INACTIVE / RETIRED) และปลดระวางสงวนไว้ให้ครุภัณฑ์
   - **แนะนำ:** วัสดุคงทนเลือกได้ พร้อมใช้งาน / ชำรุด / งดให้ยืม (INACTIVE) · มีผลกับทั้งชนิด (ERD ไม่มีสถานะรายชิ้นของวัสดุคงทน)
4. **แก้ไขข้อมูลรุ่นของครุภัณฑ์** — ครุภัณฑ์รุ่นเดียวกันเก็บแยกแถว และ ERD บอก "แก้ข้อมูลรุ่นต้องแก้ทุกชิ้นให้ตรงกัน" แต่ไม่มีคอลัมน์บอกว่าชิ้นไหนรุ่นเดียวกัน
   - **แนะนำ:** ฟอร์มแก้ไขมีช่องติ๊ก "ใช้กับทุกชิ้นที่ชื่อเดียวกัน (N ชิ้น)" ติ๊กไว้เป็นค่าเริ่มต้น · ไม่ติ๊ก = แก้เฉพาะชิ้นนี้ · ใช้ชื่อเดิมก่อนแก้เป็นตัวจับกลุ่ม
5. **แก้จำนวนทั้งหมดของวัสดุ** — ถ้ามีของถูกยืมอยู่ จำนวนคงเหลือต้องไม่ติดลบ
   - **แนะนำ:** เปลี่ยน `qty_total` แล้วปรับ `qty_available` ตามส่วนต่าง · ถ้าลดจนคงเหลือติดลบ → ไม่บันทึกและบอกจำนวนที่ถูกยืมอยู่
6. **ช่องสถานะในฟอร์ม** — mapping `21` มีช่อง `base_status` ในฟอร์ม แต่ UC-23 มีหน้าเปลี่ยนสถานะแยก
   - **แนะนำ:** ไม่ใส่ในฟอร์ม · สร้างใหม่ = พร้อมใช้งาน · เปลี่ยนสถานะผ่านหน้า UC-23 (วัสดุสิ้นเปลืองใช้ปุ่ม "ปิดการใช้งาน" จากข้อ 2)
7. **เปลี่ยนสถานะแบบกลุ่มเมื่อมีชิ้นที่ถูกยืมอยู่** — UC-23 บอก "ข้าม หรือ แจ้งเตือนไม่อนุญาต"
   - **แนะนำ:** ข้ามชิ้นที่ถูกยืม เปลี่ยนชิ้นอื่นตามปกติ แล้วแจ้ง "เปลี่ยนแล้ว X ชิ้น · ข้าม Y ชิ้นที่กำลังถูกยืม: UBU-EQ-..."
8. **ขนาดรูปสูงสุด** — UC-20 พูดถึง "ไฟล์รูปภาพเกินขนาด" แต่ไม่ระบุตัวเลข
   - **แนะนำ:** 5 MB, รับ JPG / PNG / WEBP

## 9. ข้อตัดสินใจ (ยืนยันแล้ว 2026-11-13)

| ข้อ | เลือก | ผล |
|---|---|---|
| 1 | ข้ามไปก่อน | **ไม่ทำ UC-24 (นำเข้า CSV) ในรอบนี้** · คอลัมน์ CSV ค่อยตัดสินใจตอนกลับมาทำ |
| 2 | ก. | วัสดุที่เคยถูกเบิกลบไม่ได้ → ปุ่ม "ปิดการใช้งาน" (`INACTIVE`) และ "เปิดใช้งานอีกครั้ง" |

| 7 | ก. | เปลี่ยนสถานะแบบกลุ่ม: ข้ามชิ้นที่ถูกยืมแล้วแจ้งรายชื่อ |
