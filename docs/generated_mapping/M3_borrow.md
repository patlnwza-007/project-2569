## 4. หน้าหลักนักศึกษา (UC-09) + ยกเลิก (UC-07)

การ์ด 1 ใบ = 1 คำขอ: เลขที่, วันที่ส่ง, ป้ายสถานะ, ป้ายประเภท (ถ้าเป็นประเภทเดียวล้วน), ป้าย "ยืมกรณีพิเศษ", เหตุผลไม่อนุมัติ, รายการของ + กำหนดคืนรายชิ้น + จำนวนวันที่เหลือ, ยอดค่าปรับ/ค่าชดใช้ (`total_fine`, `lost_compensation`) · แบนเนอร์ "นำของมาที่เคาน์เตอร์" เมื่อรอตรวจรับคืน · การ์ดสรุปคิว
ปุ่ม: ยกเลิก (เฉพาะ `PENDING`) · แจ้งคืน (มีของต้องคืนที่ยังไม่คืน, รอบ 3b) · แจ้งย้ายที่ตั้ง (ข้อ 6)

## 5. แจ้งคืน (UC-08) · คิว (UC-10) · ประวัติ (UC-11) · แจ้งชำรุด (UC-38) — รอบ 3b

| หน้า | บันทึก |
|---|---|
| แจ้งคืน | ติ๊กชิ้นที่คืน + สภาพ (ปกติ/ชำรุด/สูญหาย) ต่อชิ้น → `ReturnItem(qty_returned, condition_status)` · รูปหลักฐาน **บังคับ** → `ReturnRequest.return_photo` · หมายเหตุ → `ReturnRequest.note` · แสดงราคาจัดซื้อเพื่อทราบยอดชดใช้คร่าว ๆ |
| คิว | ลำดับคิว, วันคาดว่าจะได้ยืม (ข้อ 4), สถานะ, ปุ่มยืนยันรับสิทธิ์ (เมื่อ `NOTIFIED`, ภายใน 1 วัน), ออกจากคิว · คิวที่เลยเวลา → `EXPIRED` อัตโนมัติ (มีฟังก์ชันแล้วจากเฟส 1) |
| ประวัติ | คำขอที่จบแล้ว (`RETURNED`, `ISSUED`, `REJECTED`, `CANCELLED`, `EXPIRED`) + "ประเมินแล้ว X/Y ชิ้น" + ปุ่ม ⭐ ประเมิน (กดได้เมื่อทำ M5) |
| แจ้งชำรุด | เลือกประเภท: อุปกรณ์ประจำห้อง (ชื่ออุปกรณ์ + ตึก/ห้อง) หรือครุภัณฑ์ในระบบ (เลือกจาก asset tag → `DamageReport.item`, `origin_location = Item.location`) · อาการ, รูป (ข้อ 10) · `status = PENDING` · รายการที่เคยแจ้งของตัวเองพร้อมสถานะ |

## 7. ต้องตัดสินใจ

1. **ตัดสต็อกตอนไหน** — use case บอกว่าส่งคำขอแล้วสถานะ `PENDING` แล้วเจ้าหน้าที่ "ตรวจของและปล่อยของ" ใน UC-17 แต่ไม่ได้บอกว่าจำนวนคงเหลือลดตอนไหน ถ้าไม่ลดตอนส่งคำขอ นักศึกษา 2 คนอาจส่งคำขอโปรเจกเตอร์ชิ้นเดียวกันพร้อมกันได้
   - **แนะนำ:** **จองของทันทีตอนส่งคำขอ** — วัสดุ/วัสดุคงทนลด `qty_available` · ครุภัณฑ์เปลี่ยนเป็น "กำลังถูกยืม" · คืนของเข้าคลังอัตโนมัติเมื่อยกเลิก (UC-07) หรือถูกปฏิเสธ (UC-17, M6) · เข้ากับขั้นตอนจริงที่นักศึกษาหยิบของมาวางที่เคาน์เตอร์แล้ว
   - หรือ: ลดตอนเจ้าหน้าที่ปล่อยของ (UC-17) — แต่เกิดคำขอซ้อนกันได้ และเจ้าหน้าที่ต้องปฏิเสธเอง
2. **ใส่ตะกร้าจากหน้า M2** — mockup มี popup เลือกจำนวนแบบ Shopee
   - **แนะนำ:** กดแล้วใส่ 1 ชิ้นทันที (กดซ้ำ = +1) · ปรับจำนวนในหน้าตะกร้า · ไม่ทำ popup (ลดงาน ได้ผลเหมือนกัน)
3. **แบ่ง M3 เป็น 2 รอบ** — งานใหญ่ (8 UC, 7 หน้า)
   - **แนะนำ:** รอบ 3a = UC-05, 06, 07, 09 (ยืมได้ครบ) → commit → รอบ 3b = UC-08, 10, 11, 38 · ทั้ง 2 รอบใช้ mapping ไฟล์นี้ ไม่ต้องตัดสินใจซ้ำ
4. **สูตรวันคาดว่าจะได้ยืม (คิว)** — UC-10 บอกแค่ "อิงกำหนดคืนผู้ยืมปัจจุบัน + คิวก่อนหน้า"
   - **แนะนำ:** ลำดับที่ k ได้ = กำหนดคืนเร็วที่สุดของผู้ยืมปัจจุบัน + (k − 1) × วันยืมสูงสุดของสิ่งของ · ถ้าผู้ยืมปัจจุบันเป็นกรณีพิเศษ แสดงข้อความ "ผู้ยืมปัจจุบันได้รับอนุมัติยืมนานพิเศษถึงวันที่ ..." · ยังไม่ปล่อยของ (ไม่มีกำหนดคืน) → "ยังประเมินไม่ได้"
5. **แจ้งเตือนเมื่อถึงคิว** — UC-10 บอก "หน้าเว็บและอีเมล" · การแจ้งเกิดตอนเจ้าหน้าที่รับคืน (UC-18, M6)
   - **แนะนำ:** M3 เตรียมฟังก์ชันแจ้งเตือนไว้ (แบนเนอร์บนหน้าหลัก + ป้ายบนเมนูคิว + อีเมล) · อีเมลช่วงพัฒนาพิมพ์ออกหน้าจอ Terminal (ยังไม่ส่งจริง) เปลี่ยนเป็นส่งจริงทีหลังด้วยการตั้งค่า SMTP
6. **แจ้งย้ายที่ตั้งของที่ยืม** — ERD มี `BORROW_ITEM.current_location / moved_at` และ mapping `08` มีปุ่มนี้ แต่ **ไม่มี use case รองรับ**
   - **แนะนำ:** ทำ (เล็กมาก): ปุ่ม "📍 แจ้งย้ายที่ตั้ง" ที่ของที่ต้องคืนในคำขอที่กำลังยืม กรอกสถานที่ใหม่ → เจ้าหน้าที่เห็นในหน้ารายละเอียด (ทำไว้แล้วใน M2) · บันทึกลง `conflicts.md` ว่าไม่มี UC
   - หรือ: ยังไม่ทำ
7. **สถานะระหว่างคืนบางส่วน**
   - **แนะนำ:** แจ้งคืน → คำขอ = `RETURN_PENDING` และครุภัณฑ์ชิ้นที่แจ้ง = "รอตรวจรับคืน" · ชิ้นที่ไม่ได้แจ้งยังใช้ต่อได้ · หลังเจ้าหน้าที่ตรวจรับ (M6) ถ้ายังมีของค้าง คำขอกลับเป็น `BORROWING` ถ้าคืนครบ = `RETURNED` · แจ้งคืนรอบใหม่ได้เมื่อรอบก่อนตรวจรับแล้วเท่านั้น
8. **อาการชำรุด / สาเหตุสูญหายตอนแจ้งคืน** — mockup มีช่องกรอกต่อชิ้น แต่ ERD ไม่มีคอลัมน์ (mapping `09` หมายเหตุไว้)
   - **แนะนำ:** มีช่องกรอกต่อชิ้นเมื่อเลือก ชำรุด/สูญหาย แล้วรวมเป็นข้อความเก็บใน `ReturnRequest.note` เช่น "UBU-EQ-001-01: เลนส์แตก"
9. **หน้าหลัก vs ประวัติ**
   - **แนะนำ:** หน้าหลักแสดงคำขอที่ยังไม่จบ (`PENDING`, `BORROWING`, `RETURN_PENDING`) + ที่จบภายใน 7 วันล่าสุด · หน้าประวัติแสดงคำขอที่จบแล้วทั้งหมด
10. **รูปตอนแจ้งชำรุด (UC-38)** — UC ให้แนบรูป แต่ Alternative Flow บังคับแค่สถานที่/สิ่งของ
    - **แนะนำ:** รูปไม่บังคับ (บางกรณีถ่ายไม่ได้ เช่น ปลั๊กไฟในที่มืด) · ฟีเจอร์สแกน OCR asset tag ใน mockup ไม่ทำ
