## 1. เพิ่มใหม่ทั้งหมด (11 ข้อ)

ไม่มีร่องรอยใน UBorrowU เลยสักจุด

### 1.1 แดชบอร์ดสรุปภาพรวม (UC-17)
UBorrowU ไม่มีหน้าสรุปเชิงภาพเลย มีแค่หน้ารายการ (list) กับ PDF รายงาน YuemDee เพิ่มการ์ดสรุปยอดยืม-คืนปัจจุบัน + กราฟแท่งสถานะการยืม + กราฟโดนัทสัดส่วนนักศึกษาปกติ/ถูกระงับสิทธิ์

### 1.2 แบบประเมินความพึงพอใจ ฝั่งนักศึกษา (UC-15 / FR-16)
เช็คด้วย grep ทั้ง `models.py`/`views.py`/`.html` ของ UBorrowU ไม่พบคำว่า "ประเมิน"/evaluation เลยสักจุด เป็นโมเดล/ฟีเจอร์ใหม่ทั้งหมด

### 1.3 จัดการฟอร์มประเมิน + ดูสรุปผล ฝั่งเจ้าหน้าที่ (UC-32 / FR-32)
เจ้าหน้าที่ออกแบบคำถามเอง เปิด/ปิดรับแบบประเมิน ดูสถิติสรุป — ของเดิมไม่มี

### 1.4 นำเข้าคลังพัสดุเป็นชุดผ่าน CSV/Excel (UC-25 / FR-25)
UBorrowU มี bulk import แค่ฝั่งรายชื่อผู้ใช้ (`person_upload`, `person_upload_staff`) ฝั่งพัสดุต้องกดเพิ่มทีละชิ้นเท่านั้น (`staff_manage_parcel`, `staff_manage_durable` ไม่มี endpoint นำเข้าไฟล์)

### 1.5 เจ้าหน้าที่เพิ่มรายการจัดซื้อได้เอง (UC-30 / FR-30)
ของเดิมมีทางเดียวคือรอนักศึกษาเสนอแนะ (`ListFromRec`) แล้วเจ้าหน้าที่แค่อนุมัติ/ปฏิเสธ ไม่มีช่องทางให้เจ้าหน้าที่เริ่มเองได้

### 1.6 Role Override กำหนดบทบาทรายบุคคล (UC-34 / FR-34)
UBorrowU กำหนดบทบาทผ่านฟิลด์ `right` ตรงๆ ไม่มีกลไก "override" ที่แยกจากบทบาทอัตโนมัติ และไม่มี audit ว่าที่มาของบทบาทเป็นอัตโนมัติหรือถูกกำหนดเอง

### 1.7 แผนผังตำแหน่งชั้นวางแบบหน้าเว็บ (Position Map, UC-04 / FR-04)
ของเดิมมีแค่ `pdf_print_position` (พิมพ์ PDF) ไม่มีหน้าจอแสดงตำแหน่งแบบอินเทอร์แอคทีฟ

### 1.8 แจ้งเตือนอัตโนมัติเมื่อถึงคิว (ส่วนหนึ่งของ UC-11)
ยืนยันจากโค้ดว่าฟิลด์ `is_borrowed` ของ `QueueParcel`/`QueueDurable` ถูก set แค่ตอนสร้าง (False) ไม่เคยถูกอ่าน/แก้ที่ไหนอีกเลยในทั้งระบบ คิวของเดิมจึงเป็นทางตัน ไม่มีวันแจ้งเตือนหรือ promote เป็นการยืมจริง — YuemDee เพิ่ม post-condition ชัดเจนว่า "เมื่อสิ่งของว่างและถึงคิว ระบบแจ้งเตือนผ่านหน้าเว็บและอีเมลทันที"

### 1.9 เงื่อนไขบังคับสต็อก = 0 ก่อนจองคิวได้ (business rule ของ UC-11)
โค้ดเดิม `add_to_queue`/`add_to_queue_durable` ไม่มีการเช็คจำนวนคงเหลือเลย ใครก็กดจองคิวได้แม้ของยังมีสต็อกเหลือเต็ม YuemDee บังคับ precondition "สิ่งของนั้นต้องมีจำนวนคงเหลือเป็น 0" ก่อนถึงจะจองคิวได้

### 1.10 กำหนดเวลารับของภายใน 2 วัน + auto-expire (business rule ของ UC-08 / UC-18)
ของเดิมสถานะ "รอยืนยันการรับ" ค้างได้ไม่จำกัดเวลา YuemDee เพิ่มกติกาบังคับ 2 วัน เกินกำหนดดึงของคืนคลังอัตโนมัติ เปลี่ยนเป็นสถานะ "หมดอายุ" ใหม่

### 1.11 เปลี่ยนสถานะครุภัณฑ์เป็น "ครุภัณฑ์เสียหาย" อัตโนมัติ + เมนู "ครุภัณฑ์เสียหาย" (UC-36 / FR-36, เพิ่มใน v1.3)
grep ทั้งโค้ด UBorrowU หาคำว่า "เสียหาย/ชำรุด/สูญหาย/damage" เจอแค่ชื่อไฟล์ `broken_image.png` (default รูปสินค้า) ไม่เกี่ยวกับการจัดการของเสียหายเลย — ของเดิมไม่มีแนวคิดนี้แม้แต่นิดเดียว ทั้งไม่มีสถานะเฉพาะและไม่มีหน้าจอ YuemDee เพิ่มพฤติกรรมอัตโนมัติเข้าไปที่ UC-19: เมื่อเจ้าหน้าที่ตรวจรับคืนแล้วพบว่าเสียหาย ระบบเปลี่ยนสถานะรหัสครุภัณฑ์ชิ้นนั้นจาก "พร้อมให้ยืม" เป็น "ครุภัณฑ์เสียหาย" ทันที (ไม่นับเป็นจำนวนพร้อมให้ยืม) พร้อมเพิ่มเมนู sidebar ใหม่ "ครุภัณฑ์เสียหาย" (UC-36) ให้เจ้าหน้าที่ดูรายการทั้งหมดและส่งซ่อม/ยืนยันซ่อมเสร็จได้จากที่เดียว

## 2. ตัดออกทั้งหมด (9 ข้อ)

ไม่เหลือร่องรอยใน YuemDee เลยสักจุด

### 2.1 LINE Notify integration ทั้งระบบ
grep คำว่า "LINE" ในเอกสาร FR และ use case ทั้งหมดของ YuemDee เจอ 0 ครั้ง เปลี่ยนไปใช้ in-app notification + email แทน (ของเดิมยิง LINE Notify API มากกว่า 15 จุดทั่วระบบ)

### 2.2 สิทธิ์ลบครุภัณฑ์แบบ hard delete
ของเดิม `delete_staff_manage_durable` เรียก `obj.delete()` ตรงๆ ไม่มี guard ใดๆ และ `LoanDurable.durable_item` ตั้ง `on_delete=CASCADE` ไว้ด้วย แปลว่าลบครุภัณฑ์ 1 ชิ้นเท่ากับลบประวัติยืม-คืนทั้งหมดของชิ้นนั้นไปด้วย — YuemDee ยืนยันชัดใน UC-24 ว่า "ห้ามลบข้อมูลครุภัณฑ์ถาวร ให้ใช้การเปลี่ยนสถานะเพื่อเก็บ Audit Trail" (แต่วัสดุยังลบถาวรได้ตามปกติผ่าน UC-23)

### 2.3 ระบบ whitelist อัปโหลดรายชื่อล่วงหน้า
ของเดิมต้องอัปโหลด `Profile`/`ProfileStaff` ก่อน ระบบถึงกำหนดสิทธิ์ถูกต้องตอนล็อกอินได้ YuemDee เองก็มีบันทึกไว้ในเอกสารว่า orphan page `import-staff-whitelist`/`import-student-whitelist` ถูกลบออกจาก mockup แล้ว เพราะ SSO กำหนดบทบาทอัตโนมัติแทน

### 2.4 PDF export ที่กระจัดกระจาย
นับ endpoint ในโค้ดเดิมได้ 11 จุด (`pdf_print`, `pdf_borrow`, `pdf_borrow_durable`, `pdf_print_position` x2 ทั้งฝั่ง user/staff, `pdf_staff_max_borrow` x2, `pdf_staff_parcel`, `pdf_staff_durable`, `pdf_staff_queue` x2) YuemDee ยุบเหลือแค่ 4 รูปแบบรายงานตายตัว (สรุปยืม-คืนรายเดือน, ของชำรุด, คนค้างส่ง, คำเสนอแนะ) บวก CSV คลังพัสดุ 1 แบบ

### 2.5 สถานะ "คืนไม่สำเร็จ" แยกต่างหาก
ของเดิม `staff_unreturn_durable` เปลี่ยนเป็นสถานะค้างแยกที่ user เห็น YuemDee ให้ปฏิเสธรับคืนแล้วย้อนกลับไป "กำลังยืม" เฉยๆ ไม่มีสถานะนี้อีกต่อไป

### 2.6 ฟิลด์ `statustype` อิสระต่อชิ้น
ของเดิมตั้ง "ต้องคืน/ไม่ต้องคืน" ได้อิสระทีละชิ้นผ่านฟิลด์บน `Add_Parcel`/`Add_Durable` YuemDee ผูกตายตัวกับหมวดหมู่แทน (FR-09 ยืนยันชัดว่า "ครุภัณฑ์เท่านั้น...เพราะเป็นของที่ต้องคืน ส่วนวัสดุเป็นของเบิกใช้แล้วหมดไป")

### 2.7 Concept "จำนวนไม่จำกัด (∞)"
ของเดิมมี `quantitytype` เลือกได้ "∞" สำหรับวัสดุบางชิ้น (ไม่หักสต็อกจริง หักแค่ `borrow_count`) — grep ทั้งเอกสาร YuemDee ไม่พบสัญลักษณ์ "∞" หรือคำว่า "ไม่จำกัดจำนวน" เลยสักจุด แนวคิดนี้หายไปทั้งหมด

### 2.8 สถานะ "อนุมัติ" ที่ไม่เคยถูกใช้จริง
มีอยู่ใน enum `BORROWSTATUS` เดิมแต่ `staff_borrow_parcel`/`staff_borrow_durable` ข้ามสถานะนี้ไปตรงๆ (set ตรงจาก "รออนุมัติ" ไป "รอยืนยันการรับ") YuemDee รวมเป็นป้ายเดียว "อนุมัติแล้ว/รอรับของ" ให้ตรงกับพฤติกรรมจริง ไม่ทิ้งสถานะตายไว้

### 2.9 หน้ารายงาน "ยอดฮิต" (`staff_max_borrow` / `staff_max_borrow_durable`)
ของเดิมมีหน้ารายงานแยก sort/search ได้เต็มรูปแบบ (`order_by('-borrow_count')`) YuemDee ไม่มีอะไรมาแทนเลยทั้งหน้าแยกและวิดเจ็ตในแดชบอร์ด — ตัดทิ้งขาด

## 3. ปรับแก้ Flow (5 ข้อ)

ของเดิมมีอยู่แล้ว แต่เปลี่ยนพฤติกรรม/กติกา

### 3.1 Login: Google OAuth → UBU SSO
ของเดิมใช้ `django-allauth` + Google OAuth ใครมีบัญชี Google ก็ล็อกอินได้ YuemDee บังคับ UBU Single Sign-On (@ubu.ac.th) เท่านั้น ปิดช่องคนนอกมหาวิทยาลัย

### 3.2 คืนของสำเร็จ → เพิ่มจำนวนกลับคลังอัตโนมัติ
ยืนยันจากโค้ด `staff_return_durable` ของเดิม: เปลี่ยนแค่ `status = 'คืนสำเร็จ'` ไม่มีบรรทัดไหนบวกจำนวนกลับเข้า `Add_Durable.quantity` เลย YuemDee ระบุ business rule ชัดว่า "การยืนยันรับคืนจะเพิ่มจำนวนพัสดุพร้อมใช้งานในคลังกลับมาโดยอัตโนมัติ"

### 3.3 สถานะแยกตามประเภทให้เป็นทางการ + เปลี่ยนชื่อ
ของเดิมพฤติกรรมจริงก็แยกอยู่แล้ว (parcel confirm → "ยืมสำเร็จ" จบ, durable confirm → "กำลังยืม" ไปต่อ) แต่ใช้ enum 9 ค่าร่วมกันไม่เป็นทางการ YuemDee แยกเป็นทางการ + เปลี่ยนชื่อสถานะจบของวัสดุจาก "ยืมสำเร็จ" เป็น "เบิกสำเร็จ" ให้สื่อความหมายตรงกว่า

### 3.4 ฟิลด์ `numdate` — จากประมาณการคิวสู่กติกาบังคับ
ของเดิมฟิลด์นี้มีอยู่แล้วบน `Add_Durable` แต่ใช้แค่คำนวณเวลารอคิวโดยประมาณ (`waiting_period = queue_count * numdate`) ไม่เคยบังคับใช้เป็นเพดานวันคืนจริง YuemDee เปลี่ยนให้เป็นกติกาบังคับ "จำนวนวันยืมสูงสุด" ที่ครุภัณฑ์ทุกชิ้นต้องมี

### 3.5 ชื่อฟังก์ชันปฏิเสธคำขอที่สับสน
ของเดิมชื่อ `staff_unborrow_parcel`/`staff_unborrow_durable` ฟังดูเหมือน "ยกเลิกการยืม" แต่จริงๆ ทำหน้าที่ปฏิเสธคำขอ (`status = 'ไม่อนุมัติ'`) YuemDee ตั้งชื่อ endpoint ใหม่ชัดเจนกว่า (`request_reject`)

## 4. หมายเหตุระเบียบวิธี

- ข้อมูลฝั่ง UBorrowU ทั้งหมดตรวจสอบจากการ clone ซอร์สโค้ดจริงจาก GitHub แล้วอ่าน `models.py` / `views.py` / `urls.py` ของทั้ง 3 app (`myapp`, `myappstaff`, `myappSuper`)
- ข้อมูลฝั่ง YuemDee ตรวจสอบจาก `yuemdee_functional_requirements.md`, `proposal/usecase/use_case_description.md`, `mockup/yuemdee/page_description.md` ที่เป็นสถานะล่าสุดของโปรเจกต์ (หลังตัด Role Override แบบกลุ่มผ่านไฟล์ CSV และวิดเจ็ต Top 3 ยอดฮิตออกจากแดชบอร์ดแล้ว)
- ยังมีช่องว่างที่พบระหว่างวิเคราะห์แต่ **ไม่นับรวมในลิสต์นี้** เพราะยังไม่มีเลข FR/UC อย่างเป็นทางการในเอกสาร YuemDee ปัจจุบัน:
  - ศูนย์แจ้งเตือนในระบบ (ดูประวัติการแจ้งเตือนย้อนหลัง)
  - ขอขยายเวลายืมก่อนครบกำหนด (Renewal request)
  - แจ้งของชำรุด/สูญหาย**ระหว่างที่ยืมอยู่** (ก่อนถึงวันคืน) — ยังไม่มีในทั้งสองระบบเหมือนกัน นักศึกษาต้องรอถึงขั้นตอนแจ้งคืน (UC-09) ถึงจะระบุสภาพของได้ ยังไม่นับรวมในลิสต์ข้อ 1.11 เพราะข้อ 1.11 ครอบคลุมแค่ฝั่งเจ้าหน้าที่ตอนรับคืนเท่านั้น (ต่อยอดจาก UC-19 ไม่ใช่ use case ใหม่ฝั่งนักศึกษา)
