# หน้าที่ 20: เข้าสู่ระบบผ่าน SSO และตรวจสอบสิทธิ์ผู้ใช้ (`page-login.html`)
**บทบาทผู้ใช้งาน:** ผู้ใช้งานทุกคน (นักศึกษา / เจ้าหน้าที่ / ผู้ดูแลระบบ)  
**ตารางฐานข้อมูลที่เกี่ยวข้อง:** `USER`

---

## ตารางจับคู่ฟิลด์ข้อมูล (Field-Level Data Mapping)

### ส่วนที่ 1: การยืนยันตัวตนและการตรวจสอบสิทธิ์
| ลำดับ | ชื่อช่อง / ส่วนแสดงผลบนหน้าจอ (UI) | รหัส Element (`id`) | การทำงาน (CRUD) | ตาราง (Table) | ฟิลด์ในฐานข้อมูล (Column) | หมายเหตุ |
| :---: | :--- | :--- | :---: | :--- | :--- | :--- |
| 1 | **บัญชีผู้ใช้งาน UBU SSO (`@ubu.ac.th`)** | - | `SELECT` | `USER` | `USER.email`, `USER.id` | ยืนยันตัวตนผ่านบริการ UBU Single Sign-On |
| 2 | **ชื่อ-นามสกุลผู้ใช้งาน** | - | `SELECT` | `USER` | `USER.name` | ดึงข้อมูลชื่อ-สกุลจากฐานข้อมูลผู้ใช้ |
| 3 | **บทบาทเริ่มต้นจาก SSO (Default Role)** | - | `SELECT` | `USER` | `USER.role` | ค่า Enum: `STUDENT`, `STAFF`, `ADMIN` |
| 4 | **การตรวจสอบสถานะการระงับสิทธิ์ (Block Status)** | `p_login_rejectBlocked` | `SELECT` | `USER` | `USER.blocked`, `USER.block_reason` | หาก `blocked = true` ระบบจะปฏิเสธการล็อกอิน และแสดงเหตุผลการระงับสิทธิ์ |
| 5 | **กล่องข้อความแจ้งเตือนข้อผิดพลาดการเข้าสู่ระบบ** | `p_login_login-error` | `Client State` | - | - | แสดงข้อความปฏิเสธกรณีไม่มีสิทธิ์หรือถูกระงับสิทธิ์ |

---

## ผลการตรวจสอบความสอดคล้องกับ ERD
- ✅ **เชื่อมโยงตาราง `USER` สมบูรณ์:** อ้างอิงตาม `id`, `name`, `email`, `role`, `blocked`, `block_reason` ตรงตาม ERD 100%
- ✅ **การจัดการสิทธิ์ตามบทบาท (Role-Based Access Control):** นำทางไปยังหน้าหลักของแต่ละบทบาท (Student → `request-list`, Staff → `staff-dashboard`)
