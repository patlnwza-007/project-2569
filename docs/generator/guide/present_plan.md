# แผนการนำเสนอ Mockup — YuemDee (8 นาที)

> อ้างอิงจากไฟล์ mockup จริง `mockup/yuemdee/index.html` (ครอบคลุมเกือบทุก page_code ทั้ง 10 module, มีปุ่มรีเซ็ตข้อมูลตัวอย่าง, สลับ role ผ่าน login)

## หลักคิดการแบ่งเวลา

**อย่าไล่ครบ 36 use case** — เวลาไม่พอและกรรมการจะเบื่อ ให้เล่า **1 เส้นเรื่องหลัก (นักศึกษายืม-คืน) แบบเต็ม** แล้วแทรก **จุดเด่นที่ระบบอื่นทั่วไปไม่มี** สั้น ๆ 3-4 จุด แทนการ demo ทุกหน้าเท่ากันหมด

## แผนนาทีต่อนาที

| เวลา | หน้าที่โชว์ | ทำอะไร / พูดอะไร |
|---|---|---|
| **0:00–0:30** | Login → เลือก role นักศึกษา | เข้าด้วย UBU SSO (พูดสั้น ๆ ว่า auto-role จาก SSO + รองรับ Role Override) ตรงเข้า `student_home` |
| **0:30–2:15** (1:45) | `item_list` (ค้นหา/กรอง) → `item_detail` → `cart` → `request_form` → กลับ `student_home` | **เส้นเรื่องหลัก**: ค้นหาสิ่งของ → ดูรายละเอียด → เพิ่มตะกร้า → กรอกเหตุผล+วันที่ใช้งาน (เน้นว่า "บังคับกรอกวันที่เฉพาะครุภัณฑ์ วัสดุไม่ต้อง") → ส่งคำขอ → เห็นสถานะ "รออนุมัติ" |
| **2:15–3:00** (0:45) | `item_detail` (ของหมด) → `queue_list` | จุดเด่น #1: ระบบจองคิวเมื่อของหมด — คลิกจองคิว โชว์ลำดับที่ ไม่ต้องรอเช็คเองซ้ำ ๆ |
| **3:00–4:30** (1:30) | สลับ role → `staff_dashboard` → `pending_requests` (อนุมัติ) → กลับนักศึกษา `confirm_pickup` → `notify_return` → staff `return_mgmt` | วงจรยืม-คืนเต็มรอบ: เจ้าหน้าที่อนุมัติ → นักศึกษายืนยันรับของ → แจ้งคืน → เจ้าหน้าที่ตรวจรับคืน (พูดเร็ว ๆ แต่ละขั้น 15-20 วิ) |
| **4:30–5:15** (0:45) | `item_status_change` | จุดเด่น #2: ครุภัณฑ์ชำรุดไม่ลบทิ้งแต่เปลี่ยนสถานะ (เก็บ audit trail) — ต่างจาก "ลบ" ของวัสดุใน `item_delete` |
| **5:15–6:15** (1:00) | `suggestion` (นักศึกษาเสนอ) → `suggestion_review` (staff อนุมัติ) → `purchase_add` | จุดเด่น #3: ปิด loop นักศึกษาเสนอของใหม่ → staff อนุมัติ → แปลงเป็นแผนจัดซื้อทันที (โชว์ว่าเชื่อมกันจริง ไม่ใช่แค่ฟอร์มลอย ๆ) |
| **6:15–7:15** (1:00) | `staff_dashboard` (กราฟสรุป) → `report_export` | ภาพรวมเชิงบริหาร: กราฟยืม-คืน/ของนิยม + ส่งออกรายงาน PDF/CSV |
| **7:15–7:50** (0:35) | admin `role_override` | จุดเด่น #4 (ถ้าเวลาเหลือ): Role Override — ตั้งนักศึกษาหัวหน้าห้องให้มีสิทธิ์แบบ staff ได้โดยไม่ต้องแก้ที่ SSO |
| **7:50–8:00** | ปิดท้าย | สรุป 1 ประโยค + โชว์ปุ่ม "รีเซ็ตข้อมูลตัวอย่าง" ว่าเดโมซ้ำได้ |

## หน้าที่แนะนำ "ข้าม" หรือพูดถึงแค่ปากเปล่า (ไม่ต้องคลิกโชว์)

- `bulk_import`, `item_form` (เพิ่มของทีละชิ้น), `warehouse_settings`, `import_staff_whitelist`/`import_student_whitelist`, `role_override_bulk`, `student_list`/`student_permission`, `all_history` — เป็นหน้าจัดการข้อมูลพื้นฐาน (CRUD) ที่กรรมการเข้าใจได้จากคำพูดโดยไม่ต้องเห็นจริง ถ้าเวลาขาดให้ตัดกลุ่มนี้ก่อน

## Tips เชิงปฏิบัติ

1. **เตรียม state ไว้ล่วงหน้า** — ก่อนเดโม ให้ login ค้างไว้แต่ละ role ในคนละแท็บ/localStorage คนละ session, ใส่ของในตะกร้าไว้ล่วงหน้า 1 ชิ้น ไม่ต้องพิมพ์สดหน้ากรรมการ (เสียเวลาและเสี่ยงพิมพ์ผิด)
2. **กดปุ่ม "รีเซ็ตข้อมูลตัวอย่าง" ก่อนเริ่มจริง** เพื่อให้ตัวเลข/สถานะสอดคล้องกับที่ซ้อมไว้
3. **ซ้อมจับเวลาจริงอย่างน้อย 2 รอบ** — 8 นาทีมักหลุดจาก network lag ของการคลิกสลับหน้า ไม่ใช่จากการพูด
4. **มี fallback**: ถ้ากลัว WiFi ห้องสอบล่ม เปิดจากเครื่อง local (`file://`) ได้เลยเพราะ mockup นี้ standalone อยู่แล้ว ไม่ต้องพึ่ง internet
