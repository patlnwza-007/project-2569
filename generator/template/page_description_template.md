# Template — `page_description.md` (คำอธิบายรายหน้าจอของ Mockup)

> วิธีใช้: คัดลอกโครงด้านล่างไปที่ `<module>/mockup/page_description.md` แล้วแทนที่ `{{...}}` ด้วยค่าจริง
> ทำ **1 บล็อก §B ต่อ 1 ไฟล์ใน `pages/`** — จำนวนบล็อกต้องเท่ากับจำนวน state ใน `<app>/state/module_state_diagram.puml` พอดี (ไม่ขาด ไม่เกิน)
> ใช้คู่กับ [`mockup_generate_guide.md`](../guide/mockup_generate_guide.md) §4.3 และ [`mockup_template.md`](mockup_template.md)
> ดูตัวอย่างที่กรอกครบแล้วได้ที่ [`mockup_example.md`](../example/mockup_example.md)

**ไฟล์นี้มีไว้ทำอะไร:** mockup เป็นภาพที่กดได้ แต่ไม่ได้บอกว่า *ทำไม* หน้านั้นมีอยู่ และ *ใคร* ควรเห็นมัน — `page_description.md` คือคำอธิบายที่เติมช่องว่างนั้น ใช้ได้ 3 ทาง: (1) ให้กรรมการสอบ/อาจารย์ที่ปรึกษาอ่านคู่กับ screenshot โดยไม่ต้องเดา (2) ให้คนเขียน Django view/template รู้ว่าหน้านี้ต้องบังคับสิทธิ์ role ไหน (3) เป็นหลักฐาน traceability ว่าไม่มีหน้าจอไหนถูกสร้างขึ้นลอย ๆ โดยไม่มี UC รองรับ

## ที่มาของทุกหัวข้อ — ห้ามเขียนจากจินตนาการ

ทุกบรรทัดใน `page_description.md` ต้อง copy/สรุปมาจากเอกสารที่มีอยู่แล้ว **ไม่ใช่แต่งเพิ่มตอนเขียน mockup**:

| หัวข้อในไฟล์นี้ | ที่มา (แหล่งความจริง) |
|---|---|
| `page_code`, ชื่อหน้า | `<app>/state/module_state_diagram.puml` — ชื่อหลัง `as` และ page_title ([กฎการตั้ง](../guide/ui_state_diagram_generate_guide.md#4-page_code--ชื่ออ้างอิงของหน้าจอ-plantuml-alias)) |
| URL / template / ไฟล์ mockup | แปลงจาก `page_code` ตามตาราง derive ([ui_state_diagram guide §4.3](../guide/ui_state_diagram_generate_guide.md)) |
| **วัตถุประสงค์ของหน้า** | **Post-condition** ของ UC ที่หน้านี้รองรับ (post-condition บอกว่า "สุดท้ายผู้ใช้ได้อะไร" = เหตุผลที่หน้านี้มีอยู่) |
| **หน้านี้ทำอะไรได้** | **Basic Flow** ขั้นที่ actor ลงมือทำ + **transition ขาออก** ของ state นี้ในไดอะแกรม (1 transition = 1 ปุ่ม) |
| **Actor ที่เข้าถึงได้** | **Actor หลัก** ของ UC + โซน (composite state) ที่ state นี้อยู่ในไดอะแกรม |
| ข้อมูลที่แสดง / ฟิลด์ | บรรทัด `แสดง:` / `ฟิลด์:` ใน `note` ของ state |
| สถานะว่าง / ข้อผิดพลาด | บรรทัด `ว่าง:` / `ผิดพลาด:` ใน `note` (มาจาก Alternative Flow ของ UC) |
| กฎที่บังคับบนหน้านี้ | บรรทัด `กฎ:` ใน `note` (มาจาก Business Rules ของ UC) |
| เข้าหน้านี้ได้จากไหน / ออกไปไหน | transition **ขาเข้า/ขาออก** ของ state นี้ในไดอะแกรม (คำบนปุ่มต้องตรงกันคำต่อคำ) |

> ถ้ากรอกช่องไหนไม่ได้เพราะเอกสารต้นทางไม่มีข้อมูล → **ห้ามแต่งเอง** ให้ทำตาม [ui_state_diagram guide §11](../guide/ui_state_diagram_generate_guide.md) คือบันทึกไว้แล้วถามเจ้าของเอกสารก่อน

## §A · ตารางสรุปทุกหน้าจอ (ใส่ไว้ต้นไฟล์)

```markdown
# `{{module}}` / `{{app}}` — คำอธิบายรายหน้าจอ (Page Description)

> Mockup: [`index.html`](index.html) · ไดอะแกรม: [`../../{{app}}/state/module_state_diagram.puml`](../../{{app}}/state/module_state_diagram.puml)
> Use case: [`../../{{app}}/proposal/usecase_description.md`](../../{{app}}/proposal/usecase_description.md)
> จำนวนหน้าจอ: **{{n}}** หน้า (= จำนวน state ในไดอะแกรม = จำนวนไฟล์ใน `pages/`)

## A.1 สารบัญหน้าจอ

| # | `page_code` | ชื่อหน้า | วัตถุประสงค์ (1 บรรทัด) | UC | Actor ที่เข้าถึงได้ | ไฟล์ |
|---|---|---|---|---|---|---|
| 1 | `{{PageCode}}` | {{ชื่อหน้าภาษาไทย}} | {{ทำไมหน้านี้ต้องมี — สรุปจาก Post-condition}} | UC-{{nn}} | {{Actor}} | [`pages/page-{{page-code-kebab}}.html`](pages/page-{{page-code-kebab}}.html) |
| 2 | ... | ... | ... | ... | ... | ... |

## A.2 ตารางสิทธิ์การเข้าถึง (Actor × หน้าจอ)

ใช้ยืนยันว่าเมนู/หน้าไหนต้องซ่อนจาก role ใด — ตรงกับ `data-roles` ใน sidebar ของ mockup และ `UserPassesTestMixin` ในหน้าจริง

| `page_code` | {{Actor 1}} | {{Actor 2}} | {{Actor 3}} | หมายเหตุสิทธิ์ |
|---|:---:|:---:|:---:|---|
| `{{PageCode1}}` | ✅ | — | — | {{เช่น เห็นเฉพาะข้อมูลของตัวเอง}} |
| `{{PageCode2}}` | ✅ | ✅ | — | {{เช่น Actor 2 เห็นทุกคน แต่ Actor 1 เห็นแค่ของตัวเอง}} |
| `{{PageCode3}}` | — | — | ✅ | {{เช่น ต้องเป็น superuser}} |

> **✅ = เปิดหน้านี้ได้** · **— = เปิดไม่ได้ (ต้องไม่เห็นเมนู และเข้า URL ตรงต้องถูกปฏิเสธ)**
> ถ้า role หนึ่งเห็นหน้าเดียวกันแต่เห็น**ข้อมูลไม่เท่ากัน** ให้ใส่ ✅ ทั้งคู่แล้วอธิบายความต่างในคอลัมน์หมายเหตุ — ห้ามแยกเป็น 2 หน้าถ้าไดอะแกรมมี state เดียว
```

## §C · ท้ายไฟล์ — สิ่งที่ *ไม่มี* หน้าจอ (บังคับใส่)

```markdown
---

## UC ที่ไม่มีหน้าจอในโมดูลนี้

| UC | ชื่อ Use Case | เหตุผลที่ไม่มีหน้าจอ |
|---|---|---|
| UC-{{xx}} | {{ชื่อ UC}} | {{background job / scheduled task — ไม่มี actor กดปุ่ม}} |
| UC-{{yy}} | {{ชื่อ UC}} | {{เป็น API ให้ app อื่นเรียก ไม่มี UI}} |

## พฤติกรรมอัตโนมัติของระบบ (ไม่ใช่หน้าจอ ไม่ใช่ปุ่ม)

- {{เช่น การแจ้งเตือน in-app + อีเมลเมื่อ... — ผูกกับ UC-nn}}
- {{เช่น auto-expire คำขอที่ไม่มารับภายใน N วัน — ผูกกับ UC-nn}}
```

> ส่วน §C สำคัญเท่ากับ §B — ถ้าไม่มีส่วนนี้ คนอ่านจะนับ UC ไม่ครบแล้วสรุปว่า mockup ทำไม่เสร็จ

## Checklist ก่อนส่ง `page_description.md`

- [ ] จำนวนบล็อก §B = จำนวน state ใน `module_state_diagram.puml` = จำนวนไฟล์ใน `pages/` (นับได้ตรงทั้ง 3 ที่)
- [ ] ทุกบล็อกมี `page_code` ตรงกับชื่อหลัง `as` ในไดอะแกรมแบบตรงตัว (ไม่ใช่ชื่อที่ตั้งใหม่)
- [ ] **วัตถุประสงค์** ทุกหน้าสรุปจาก Post-condition ของ UC — ไม่ใช่คำบรรยายหน้าตา ("หน้านี้มีตารางและปุ่มสีน้ำเงิน" = ผิด)
- [ ] **Actor ที่เข้าถึงได้** ตรงกับ Actor หลักของ UC และตรงกับโซน role ที่ state นั้นอยู่ในไดอะแกรม
- [ ] ตาราง A.2 ครบทุกหน้า × ทุก role และตรงกับ `data-roles` ใน sidebar ของ mockup
- [ ] ข้อความบนปุ่มในตาราง "การนำทาง" ตรงกับ label ของ transition ในไดอะแกรม **คำต่อคำ** และตรงกับปุ่มในไฟล์ mockup จริง
- [ ] ทุกแถวใน "สถานะว่างและข้อผิดพลาด" อ้าง UC ได้ และ trigger ได้จริงใน mockup (ไม่ใช่เขียนไว้แต่กดไม่ได้)
- [ ] มีส่วน §C ครบ — UC ที่ไม่มีหน้าจอ + พฤติกรรมอัตโนมัติ
- [ ] ไม่มีหัวข้อไหนที่ "แต่งเพิ่ม" โดยไม่มีในเอกสารต้นทาง (ถ้ามีจุดที่เอกสารขาด ต้องถามก่อน ไม่ใช่เติมเอง)
