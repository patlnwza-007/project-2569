# บทที่ 1 {#บทที่-1}

บทนำ

## 1.1 ที่มาและความสำคัญ {#1.1-ที่มาและความสำคัญ}

ในปัจจุบัน มหาวิทยาลัยอุบลราชธานีมีการนำระบบสารสนเทศมาสนับสนุนการให้บริการแก่นักศึกษาและบุคลากรในหลายด้าน เช่น ระบบ UBU Booking Hub ของสำนักวิทยบริการที่ให้บริการจองห้องประชุม ห้องศึกษากลุ่ม และพื้นที่ Makerspace ผ่านช่องทางออนไลน์ อย่างไรก็ตาม สำหรับงานยืม-คืนวัสดุสิ้นเปลือง (Consumables) และครุภัณฑ์ (Durable Articles) ซึ่งเป็นทรัพย์สินทางกายภาพของคณะและหน่วยงานต่าง ๆ ภายในมหาวิทยาลัย กระบวนการดังกล่าวยังคงดำเนินการด้วยวิธีดั้งเดิม เช่น การจดบันทึกลงสมุดกระดาษ การขออนุมัติผ่านแบบฟอร์มเอกสาร หรือการบันทึกข้อมูลผ่านโปรแกรมตารางสเปรดชีต (Spreadsheet) ซึ่งข้อมูลคลังพัสดุและช่องทางการขอยืมยังกระจัดกระจายตามแต่ละหน่วยงาน ขาดระบบศูนย์กลางที่ผู้ใช้งานสามารถเข้าถึงข้อมูลร่วมกันได้

นอกจากนี้ กระบวนการยืม-คืนพัสดุในรูปแบบเดิมยังก่อให้เกิดปัญหาต่อทั้งนักศึกษาและเจ้าหน้าที่ ในส่วนของนักศึกษา การตรวจสอบว่าพัสดุชิ้นใดพร้อมให้ยืมหรือไม่จำเป็นต้องเดินทางมาสอบถามด้วยตนเอง เนื่องจากไม่มีระบบแสดงจำนวนคงเหลือแบบเรียลไทม์ (Real-time) ในส่วนของเจ้าหน้าที่ การจัดการเอกสารกระดาษมักพบปัญหาข้อมูลจำนวนคงเหลือไม่ตรงกับพัสดุจริงในคลัง ประวัติการยืมย้อนหลังสืบค้นได้ยากหรือสูญหาย รวมถึงไม่มีกลไกอัตโนมัติในการติดตามวันครบกำหนดคืนครุภัณฑ์และการระงับสิทธิ์ (Block) ผู้ใช้งานที่ค้างส่งพัสดุคืน ส่งผลให้การบริหารจัดการคลังพัสดุโดยรวมขาดประสิทธิภาพ

จากปัญหาดังกล่าว ผู้พัฒนาจึงได้พัฒนาเว็บแอปพลิเคชันระบบยืม-คืนพัสดุออนไลน์ ภายใต้ชื่อ "UBORROWU" เพื่อเป็นระบบศูนย์กลางสำหรับการสืบค้นข้อมูลพัสดุพร้อมแผนผังตำแหน่งจัดเก็บ (Position Map) การทำรายการยืม-คืนผ่านระบบตะกร้าออนไลน์ และการจัดการคิวจองเมื่อพัสดุมีไม่เพียงพอสำหรับนักศึกษา รวมทั้งแดชบอร์ด (Dashboard) สรุปข้อมูลคลังและระบบจัดการสิทธิ์ผู้ใช้งานสำหรับเจ้าหน้าที่ ซึ่งจะช่วยลดข้อผิดพลาดจากการบันทึกข้อมูลด้วยมือ เพิ่มความรวดเร็วในการดำเนินงาน และสนับสนุนการจัดสรรทรัพยากรของมหาวิทยาลัยให้เกิดประโยชน์สูงสุด


## 1.2 วัตถุประสงค์ {#1.2-วัตถุประสงค์}

1.2.1 เพื่อพัฒนาเว็บแอปพลิเคชันระบบยืม-คืนพัสดุออนไลน์ (UBORROWU) ที่รองรับผู้ใช้งาน 3 กลุ่ม ได้แก่ นักศึกษา เจ้าหน้าที่ และผู้ดูแลระบบ สามารถดำเนินการยืม-คืนวัสดุและครุภัณฑ์ได้ครบวงจรผ่านช่องทางออนไลน์
1.2.2 เพื่อให้นักศึกษาสามารถตรวจสอบจำนวนพัสดุคงเหลือและตำแหน่งจัดเก็บได้แบบเรียลไทม์ รวมถึงจองคิวรอรับพัสดุเมื่อสิ่งของถูกยืมหมด โดยไม่ต้องเดินทางมาสอบถามด้วยตนเอง
1.2.3 เพื่อแทนที่กระบวนการจัดการคลังพัสดุด้วยเอกสารกระดาษ ให้เจ้าหน้าที่สามารถบริหารข้อมูลคลัง อนุมัติคำขอ และสืบค้นประวัติการยืม-คืนย้อนหลังได้จากระบบส่วนกลาง

## 1.3 ขอบเขตของโครงงาน {#1.3-ขอบเขตของโครงงาน}

### 1.3.1 ขอบเขตด้านการพัฒนาระบบและฮาร์ดแวร์
1. ระบบได้รับการพัฒนาในรูปแบบเว็บแอปพลิเคชัน (Web Application) สถาปัตยกรรมแบบ Monolith ด้วย Django Framework (Python) ร่วมกับ HTML, Tailwind CSS, htmx และ Alpine.js
2. ระบบรองรับการเข้าถึงและใช้งานผ่านโปรแกรมเว็บเบราว์เซอร์ (เช่น Google Chrome, Mozilla Firefox, Safari) บนอุปกรณ์คอมพิวเตอร์ส่วนบุคคล (Desktop/Laptop) และอุปกรณ์เคลื่อนที่ (Smartphones/Tablets) ที่ใช้ระบบปฏิบัติการ Windows, macOS, Android และ iOS
3. ระบบเชื่อมต่อการลงชื่อเข้าใช้งานด้วยบริการยืนยันตัวตน Google OAuth 2.0 ผ่านการตรวจสอบสิทธิ์จากรายชื่อผู้มีสิทธิ์ใช้งาน (Whitelist)

### 1.3.2 ขอบเขตด้านข้อมูล
1. ชุดข้อมูลที่ศึกษาและจัดการในระบบ ได้แก่ ข้อมูลคลังพัสดุและครุภัณฑ์ของมหาวิทยาลัยอุบลราชธานี จำแนกออกเป็น 2 ประเภท คือ **วัสดุสิ้นเปลือง** (เบิกใช้งานแล้วหมดไป) และ **ครุภัณฑ์** (ยืมใช้งานชั่วคราวและต้องนำส่งคืนตามกำหนด)
2. ข้อมูลผังตำแหน่งจัดเก็บพัสดุ (Position Map), ข้อมูลประวัติการยืม-คืน, ข้อมูลคิวจอง, ข้อมูลการระงับสิทธิ์ผู้ใช้งาน (Block) และข้อมูลสรุปแบบประเมินความพึงพอใจ
3. ข้อมูลทั้งหมดถูกจัดเก็บและบริหารจัดการด้วยระบบจัดการฐานข้อมูลเชิงสัมพันธ์ PostgreSQL (Relational Database Management System)

### 1.3.3 ขอบเขตด้านกลุ่มผู้ใช้งาน
1. **นักศึกษา (Student):** ผู้ใช้งานที่มีสิทธิ์สืบค้นพัสดุ ยื่นส่งคำขอยืม คืน จองคิว และติดตามประวัติการยืมพัสดุของตนเอง
2. **เจ้าหน้าที่ (Staff):** ผู้ปฏิบัติงานคลังที่มีสิทธิ์อนุมัติ/ปฏิเสธคำขอ ตรวจรับคืนครุภัณฑ์ จัดการข้อมูลคลัง และควบคุมสิทธิ์ผู้ยืม
3. **ผู้ดูแลระบบ (Admin):** ผู้ควบคุมระบบที่มีสิทธิ์จัดการบัญชีผู้ใช้งาน กำหนดบทบาทเฉพาะบุคคล (Role Override) และนำเข้ารายชื่อ Whitelist

### 1.3.4 ข้อจำกัดและสิ่งที่อยู่นอกขอบเขตของโครงงาน
1. โครงงานนี้มุ่งเน้นการพัฒนาและทดสอบระบบต้นแบบ (Prototype System) ในเชิงฟังก์ชันการทำงาน (Functional Testing) ภายในสภาพแวดล้อมจำลอง ยังไม่ครอบคลุมการนำไปติดตั้งใช้งานจริงในระดับโปรดักชัน (Production Deployment) หรือการทดสอบภาระการใช้งานหนัก (Load/Performance Testing)
2. ระบบไม่ครอบคลุมการเชื่อมต่อกับระบบชำระเงินหรือการคิดค่าปรับ/ค่าเสียหายพัสดุชำรุด
3. ระบบไม่รวมการส่งข้อความแจ้งเตือนผ่านช่องทางภายนอก เช่น SMS หรือ LINE Notification (การแจ้งเตือนทั้งหมดทำผ่านหน้าเว็บแอปพลิเคชันเท่านั้น)

*(หมายเหตุ: สำหรับรายละเอียดฟังก์ชันการทำงานทั้งหมดของระบบ [Functional Requirements] จะถูกระบุอย่างละเอียดในบทที่ 3)*


## 1.4 ประโยชน์ที่คาดว่าจะได้รับ {#1.4-ประโยชน์ที่คาดว่าจะได้รับ}

1.4.1 **ด้านนักศึกษา:** สามารถสืบค้นข้อมูลพัสดุ ตรวจสอบจำนวนคงเหลือและตำแหน่งจัดเก็บได้แบบเรียลไทม์ ยื่นคำขอยืม-คืน และจองคิวผ่านระบบออนไลน์ได้อย่างสะดวก รวดเร็ว ช่วยลดเวลาและภาระในการเดินทางมาสอบถามด้วยตนเอง
1.4.2 **ด้านเจ้าหน้าที่:** สามารถบริหารจัดการข้อมูลคลังพัสดุ อนุมัติคำขอยืม ตรวจรับคืนครุภัณฑ์ และสืบค้นประวัติย้อนหลังผ่านระบบส่วนกลาง ช่วยลดข้อผิดพลาด ป้องกันเอกสารสูญหาย และเพิ่มความรวดเร็วในการปฏิบัติงาน
1.4.3 **ด้านองค์กรและมหาวิทยาลัย:** มหาวิทยาลัยมีระบบสารสนเทศคลังข้อมูลพัสดุแบบรวมศูนย์ที่ถูกต้องและเป็นปัจจุบัน ป้องกันการสูญหายของพัสดุและเอกสาร พร้อมรายงานสรุปแดชบอร์ดสำหรับสนับสนุนการวางแผนจัดซื้อและบริหารจัดสรรทรัพยากรได้อย่างมีประสิทธิภาพ


## 1.5 เครื่องมือที่ใช้ในการพัฒนา (Development Tools) {#1.5-เครื่องมือที่ใช้ในการพัฒนา-(development-tools)}

### 1.5.1 ฮาร์ดแวร์ (Hardware)

1. เครื่องคอมพิวเตอร์ส่วนบุคคลที่ใช้สำหรับพัฒนาและทดสอบระบบของโครงงานโดยมีคุณสมบัติดังนี้:
   - โน้ตบุ๊ก (Notebook): Apple MacBook Air (M1, 2020)
   - หน่วยประมวลผลกลาง (CPU): Apple M1 chip (8-core CPU)
   - หน่วยความจำหลัก (RAM): Unified Memory ขนาด 8 GB
   - หน่วยประมวลผลกราฟิก (GPU): Apple M1 Integrated GPU
   - พื้นที่เก็บข้อมูล (Storage): SSD ขนาด 256 GB
   - ระบบปฏิบัติการ (Operating System): macOS


### 1.5.2 ซอฟต์แวร์ (Software)

1. **Visual Studio Code:** ใช้เป็นเครื่องมือหลัก (Source Code Editor) ในการเขียนโค้ด พัฒนา และจัดการไฟล์ต่าง ๆ ของเว็บแอปพลิเคชัน
2. **Django Framework:** เว็บเฟรมเวิร์กหลักของระบบฝั่งเซิร์ฟเวอร์ด้วยสถาปัตยกรรม Model-View-Template (MVT) สำหรับประมวลผลตรรกะทางธุรกิจ (Business Logic) ในรูปแบบ Monolith Architecture
3. **Tailwind CSS:** ยูทิลิตี้ CSS เฟรมเวิร์กสำหรับออกแบบและตกแต่งส่วนแสดงผลผู้ใช้งาน (User Interface) ให้สวยงาม และรองรับการแสดงผลแบบตอบสนอง (Responsive Design)
4. **htmx:** เครื่องมือสำหรับจัดการการส่งคำขอแบบไม่พร้อมกัน (Asynchronous AJAX Request) เพื่ออัปเดตข้อมูลบนหน้าเว็บเฉพาะส่วน (Partial Page Reload)
5. **Alpine.js:** จาวาสคริปต์เฟรมเวิร์กขนาดเล็กสำหรับจัดการสถานะเชิงโต้ตอบ (Interactive UI State) ฝั่งเบราว์เซอร์
6. **django-allauth:** โมดูลสำหรับจัดการระบบการยืนยันตัวตนผู้ใช้งานและการลงชื่อเข้าใช้งานด้วยบัญชี Google (Google OAuth 2.0)
7. **Git และ GitHub:** ระบบควบคุมเวอร์ชันซอร์สโค้ด (Version Control System) สำหรับบันทึกประวัติ ติดตามการเปลี่ยนแปลง และจัดเก็บชุดคำสั่งของโปรเจกต์
8. **Google Chrome:** เว็บเบราว์เซอร์สำหรับทดสอบการแสดงผล ตรวจสอบ UX/UI และใช้ DevTools ในการดีบักระบบ

### 1.5.3 ภาษาโปรแกรมที่ใช้

1. **Python:** ภาษาหลักในการเขียนตรรกะระบบฝั่งเซิร์ฟเวอร์ (Back-end) การประมวลผลข้อมูล และการจัดการฐานข้อมูลผ่าน Django ORM
2. **HTML5:** ภาษาไฮเปอร์เท็กซ์สำหรับสร้างโครงสร้างหน้าเว็บแอปพลิเคชัน
3. **JavaScript:** ภาษาสำหรับเขียนตรรกะการทำงานฝั่งผู้ใช้ (Client-side) ร่วมกับ htmx และ Alpine.js

### 1.5.4 ฐานข้อมูลที่ใช้

1. **PostgreSQL:** ระบบบริหารจัดการฐานข้อมูลเชิงสัมพันธ์ (Relational Database Management System - RDBMS) สำหรับจัดเก็บข้อมูลผู้ใช้งาน ข้อมูลคลังพัสดุและครุภัณฑ์ ประวัติการยืม-คืน ข้อมูลคิวจอง และสิทธิ์การเข้าถึงระบบ
